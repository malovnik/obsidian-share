## Hypotheses

1. The largest historical charge driver is app memory, not CPU.
2. The latest app memory is much lower than the 24h average, likely because the fresh deploy reset a long-lived process state or changed the running deployment.
3. The main DB storage pressure is image bytea storage, not notes.
4. Removing `db:push` from `start` will reduce deploy/start DB work and remove an avoidable production mutation from every restart.
5. The cost target near `$5/month` may be reachable without Go if latest memory holds near `0.15 GB`.
6. If app memory climbs again over 24-72h, investigate Next process growth, image handling, SSR DB paths, and long-lived caches before considering Go.
