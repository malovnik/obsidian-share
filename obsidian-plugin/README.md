# Share to Your Server — Obsidian Plugin

Плагин для Obsidian, который публикует заметки на ваш self-hosted сервер (веб-часть лежит в корне этого репозитория). Поддерживает публичные и приватные ссылки, автозагрузку изображений, перенос темы оформления и авто-синхронизацию обновлений.

## Возможности

- **Опубликовать заметку** — создаёт публичную ссылку вида `https://ваш-домен/s/<slug>`
- **Поделиться приватно** — ссылка с `noIndex`, не попадает в поиск и sitemap
- **Обновить статью** — перезалить изменения уже опубликованной заметки
- **Авто-синхронизация** — раз в час плагин обновляет все ранее опубликованные заметки
- **Синхронизация статусов** — чистит `share_url` из frontmatter, если заметка удалена с сервера
- **Изображения** — `![[image.png]]` автоматически загружаются на сервер и заменяются на публичные URL
- **Тема оформления** — цвета заголовков, ссылок, кода и т.д. переносятся на публичную страницу через `customCss`

## Установка (ручная)

У плагина нет публикации в Community Plugins, ставим вручную.

1. Откройте папку вашего vault'а в файловом менеджере.
2. Перейдите в `.obsidian/plugins/` (папка скрытая — включите показ скрытых файлов).
3. Создайте подпапку `obsidian-share-custom`.
4. Скопируйте в неё три файла из этого каталога:
   - `manifest.json`
   - `main.js`
   - (опционально) `styles.css` — если появится в будущих версиях
5. В Obsidian: **Settings → Community plugins → включите Community plugins** (если ещё не включены) → нажмите **Reload plugins** → найдите **Share to Your Server** в списке Installed plugins и включите переключатель.

> Если Obsidian не видит плагин — проверьте, что структура `.obsidian/plugins/obsidian-share-custom/manifest.json` корректна и перезапустите Obsidian.

## Настройка

После включения плагина откройте **Settings → Share to Your Server**:

| Поле | Значение |
|---|---|
| **URL API сервера** | Адрес вашего развёрнутого сервера, например `https://notes.example.com`. Без слеша в конце. |
| **Автоматически копировать ссылку** | Копировать ссылку в буфер обмена сразу после публикации. |
| **Срок жизни ссылки (дни)** | `0` = бессрочно, любое положительное число = автоудаление через N дней. |

## Как развернуть сервер

Серверная часть (Next.js + PostgreSQL) лежит в корне этого репозитория. Инструкции по деплою на Railway — в корневом `README.md`. Коротко:

1. Форкните репозиторий.
2. Создайте проект на [railway.app](https://railway.app), добавьте PostgreSQL.
3. Подключите форк, выставьте `DATABASE_URL` и `NEXT_PUBLIC_BASE_URL`.
4. Дождитесь деплоя, привяжите свой домен.
5. Подставьте полученный URL в настройки плагина.

## Использование

После настройки появятся команды (Cmd/Ctrl+P):

- **Опубликовать заметку** — публичная ссылка
- **Поделиться приватно** — скрытая ссылка
- **Обновить текущую статью на сервере** — перезалить именно эту заметку
- **Обновить все опубликованные статьи** — ручной запуск массового обновления
- **Синхронизировать статус статей** — чистка фронтматтера от «мёртвых» ссылок

Также в левом тулбаре появятся две иконки: **share** (публично) и **lock** (приватно).

После публикации плагин записывает в frontmatter заметки:

```yaml
share_url: https://notes.example.com/s/abcd1234
share_mode: public 🔓   # или private 🔒
share_id: abcd1234
```

Эти поля трогать руками не нужно — они используются для обновления и синхронизации.

## Сборка из исходников (опционально)

Если хотите пересобрать `main.js` самостоятельно:

```bash
cd obsidian-plugin
npm install
npm run build
```

На выходе получите обновлённый `main.js` в этой же папке.
